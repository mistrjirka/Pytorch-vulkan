# Audit: Vulkan backend universality (source @ b80a1f6) vs PyTorch CUDA

**Method.** Read-only. Reviewed `source/csrc/ops/{convolution,mm,bmm}.cpp`, `vulkan_context.cpp`, `vulkan_allocator.cpp`, tiling/GEMM shaders, and the pinned CUDA refs `cuda_refs/{Convolution.cpp,Conv_v8.cpp}`. Docs were treated as untrusted; current source wins. Installed 2.14.1 runtime not consulted.

**Verdict.** Within a *declared domain* — FP32, rank‑4, non‑transposed, arbitrary groups/stride/dilation — convolution dispatch is a genuinely reusable framework, not a model whitelist. Outside that domain, and for cross‑device performance portability, coverage collapses (mostly to explicit failure).

## What is universal (GPU native)

- **Candidate abstraction is graph‑generic.** `ConvKind{Direct,Depthwise,Tiled,Reduce}` × `ConvPhase{Forward,Input,Weight,Bias}` with a compile‑time tile menu (`convolution.cpp:160-167`). A candidate is explicitly “a reusable implementation, not a model or an exact tensor size” (`:158-159`).
- **Eligibility is separated from ranking and always leaves a fallback.** `applicable()` checks device limits/storage/workspace (`:226-248`); `candidates()` raises only if *no* implementation fits (`:249-262`); `heuristic()` then falls back through smaller tile → Reduce → Direct → `available.front()` (`:306-316`). So 10×10 and 11×11 both resolve, because shapes are runtime push constants and the *tile only partitions work*: `conv2d_tile_config.glsl:1-2`, `conv2d_tiled_body.glsl:34-58`. Tile‑edge shapes are bounds‑checked (`conv2d_tiled_body.glsl:13-19,38-51`), and depthwise covers arbitrary `kh/kw/stride/pad/dilation` at runtime (`conv2d_depthwise.comp:5,30-38`).
- **Layout normalization is GPU native.** `packed()` re‑stores arbitrary strided/offset views via the `conv2d_pack` shader, not the host (`convolution.cpp:61-98`), so non‑contiguous/channels-last inputs are handled on‑device.
- **Hardware limits are queried for conv and bmm.** `conv_device_properties()` is cached once (`:29-32`) and used for work‑group counts/sizes, shared memory, storage range (`:82-92,207-247,385-392`). `bmm` gates on `device_limits()` and, when outside the envelope, uses an explicit CPU fallback (`bmm.cpp:22-34`). `bmm_strided.comp:8-11,20-29` supports per‑batch offsets/transposed strides.
- **The plan cache is correctly pointer‑free.** It stores only `ConvCandidate` IDs keyed by device + phase + budget + mode flags + push‑constant shape + tensor *types* (`:366-381`, `:348-354`). The historical “pipeline keyed on recycled pointer” bug is **not** present in current source: the algorithm cache now keys on `VkBuffer` handle + offset + range (`vulkan_context.cpp:414-428`, comment `:417-418`). Do not re‑report it.

## Ranked, source‑grounded issues

**1. (High, coverage) Convolution is hard‑wired to 4‑D FP32, and unsupported configurations *fail* rather than fall back.** `convolution_params` rejects `transposed` and non‑4D (`convolution.cpp:108-110`); `buffer()` requires FP32 (`:40`). Because `convolution_overrideable` is a real PrivateUse1 implementation (`:517-519`), `conv1d`/`conv3d`/`ConvTranspose2d`/FP16 hit `TORCH_CHECK`, *not* the boxed CPU fallback (`mm.cpp:950-952`). CUDA always has native slow/1D/3D/transposed paths (`Convolution.cpp:1013-1209`) and dtype‑specific kernels; here they are explicit failures. This is the biggest gap vs “general PyTorch support like CUDA.”

**2. (Medium‑High, device portability) `mm`/`addmm` dispatch never queries hardware limits.** Kernel choice is `M>=256 && N>=256 && K>=64` only (`mm.cpp:270-277`), then `wg_x=(N+15)/16` (`:276,276-277` for tile 64) is dispatched with no `maxComputeWorkGroupCount`/`maxComputeWorkGroupInvocations`/shared‑memory check (`:283-291`). The register tile implicitly assumes `(16×4 + 4×16)`‑scale shared storage exists. Unlike conv/bmm, an oversized grid or low‑limit device yields invalid dispatch with no fallback. Also `mm_raw` (`mm.cpp:185-226`) is fully host‑memcpy and **unregistered** (registrations `:919-948`) — dead code that inflates the “GPU matmul” surface.

**3. (Medium, hidden host work) Several native handlers silently execute on the host.** `contiguous_for_kernel` falls back to `host_mirror(...).contiguous().to(device)` for non‑float/long or rank>8 (`mm.cpp:43-59`); `host_mirror` synchronizes and maps host memory (`:31-41`). `vulkan_to_copy` casts via CPU + `memcpy` (`:400-417`); `embedding` casts indices through `.to(at::kFloat)` (`:654`); `vulkan_softmax` drops to `at::_softmax(self.cpu())` when unpackable (`:533-534`); the non‑fused `addmm` path broadcasts/materializes operands (`:755-767`). These look like GPU ops in a graph but are CPU round‑trips — invisible universality limits unless `TORCH_VULKAN_TRACE_FALLBACK` is set (`:904-917`).

**4. (Medium, correctness risk — unverified) Cache‑hit mutation vs deferred dispatch.** On an algorithm‑cache hit, `get_or_create_algorithm` mutates the shared algorithm’s push constants and workgroup in place (`vulkan_context.cpp:440-454`) while still holding the cache mutex. In deferred/resident mode a prior `enqueue_compute` has already recorded `kp::OpAlgoDispatch(algorithm)` referencing that same object (`:315-341`), and conv *always* re‑executes the winner through this path (`convolution.cpp:456-458`). If two queued ops share a buffer set but have different shapes/consts, the earlier recorded dispatch may observe the later constants. I did not trace Kompute’s record‑time vs eval‑time constant binding, so this is flagged **unverified**, but the ownership model is worth an explicit test.

**5. (Low‑Medium, domain bias) Ranking is hand‑tuned, autotune is off and bounded.** `heuristic` thresholds (`cin>=8`, `cols>=16`, `rows>=32`, `n*h*w>=32`, `cols*cout>4096`) are a fixed prior (`convolution.cpp:296-305`); `TORCH_VULKAN_CONV_AUTOTUNE` defaults off and only times a *shortlist* that can exclude Direct (`:407-413`). Function is universal; *performance* across neighboring geometries is not guaranteed — the code says so itself (“shortlist, not exhaustive search”, `:409-410`). CUDA delegates this to cuDNN heuristics/FIND over a large engine space (`Conv_v8.cpp:811-863,1152-1301`).

**6. (Low) Device/limit edge assumptions.** Tiled/Direct/Depthwise require `maxComputeWorkGroupInvocations>=128` (`convolution.cpp:234-237`); on a hypothetical device below that, `candidates()` throws “no compatible implementation” (`:259-260`). `packed()` throws if the pack grid’s second dimension exceeds the limit (`:86-88`). These are limit‑aware, but they are hard failures rather than a slower path.

**7. (Low) Single‑physical‑device scoping.** `VulkanContext` exposes one logical device chosen by `TORCH_VULKAN_PHYSICAL_DEVICE_INDEX` (`vulkan_context.cpp:22-41`); the conv plan key includes vendor/device/driver (`convolution.cpp:371`), but the algorithm cache and allocator are process‑global (`vulkan_context.cpp:414-428`, `vulkan_allocator.cpp:12-15`). Fine for the declared single‑device domain; not multi‑GPU general.

## Design vs. coverage vs. performance

The candidate/eligibility/ranking/cache split and the runtime‑parameterized tiling shaders are a **sound universal design** for arbitrary NCHW FP32 graphs — including arbitrary groups, dilation, stride, kernel size, and neighboring 10×10/11×11 outputs — with a correctness‑preserving fallback chain. The remaining gaps are **coverage** (rank/dtype/transpose, #1), **device‑limit gating and fallback consistency** outside conv/bmm (#2, #6), **hidden host execution** (#3), and **performance portability** of the hand‑tuned heuristic (#5). The pointer‑recycling cache bug of the historical docs is absent in current source.

## Unverified

`conv2d_tile_store/accumulate.glsl`, `conv2d_backward_*_tiled*` bodies (non‑multiple‑of‑tile/partial‑tile correctness for register `RM=RN=2`); `matmul_strided_reg*.comp` stride support on the stride‑aware `mm` path (`mm.cpp:283-291`); attention registration despite `attention.comp` (mm.cpp `:783-786,939-941` says the legacy SDPA was removed — not traced); and the deferred cache‑mutation race in #4.
